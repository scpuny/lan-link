## D4 局域网短码落地（用户「继续执行」，接 F1–F33 之后）
规格文档 `docs/lanlink-lan-code-PRD.md`（新建）。核心设计：**短码不携带地址**，只是 30bit 随机索引；通过 UDP 广播用短码换取完整 serial，握手/传输 100% 复用外网序列号已落地的 FSM 与 transfer 引擎。详见 `feature-inventory.md` §12。

### 后端
- `discovery.rs` 扩展 UDP 42211 报文：在原 ANNOUNCE 上加 `Packet{k,c,s,q}` 统一结构，新增 `LQ`(查询)/`LA`(应答)。持有方内存注册表 `code→serial`；`generate_code()`(uuid低30bit→6×Base32)、`valid_code()`。关闭可发现即清短码。额外向 127.0.0.1 直投 LQ 支持单机回环自测。
- `lib.rs` 新增 `build_lan_candidates()`(仅私网IPv4/ULA，不写公网端点——PRD §516 安全要求)；两个 command：`generate_lan_code`(造码+造serial+register+start_host)、`connect_lan_code(code,target_addr,files)`(广播查询→decode→connect_as_receiver，target_addr 优先拨号)。
- 生成方=Initiator(收方落盘)、连接方=Receiver(发方)，与外网序列号角色一致。

## 收尾：接通 TTL 设置到 generate_serial（最后一项已知残留）
- 现象：设置页 TTL 900s/300s 已写 `ll-settings-v1`，但未传给后端，生成倒计时恒为 15 分钟。
- 链路已打通：`GenerateDialog.readSavedTtl()` 读 `ll-settings-v1.ttl` → invoke `generate_serial` 增 `ttlSecs` 参数 → Rust `generate_serial` 新增 `ttl_secs: Option<u32>` 并回写 `GenerateResult.ttl`（缺省回落 DEFAULT_TTL_SECS=900）→ 前端倒计时/参数卡/表单提示按返回值显示；`mockGenerateSerial` 同步接收 `ttlSecs`。
- 注意：Tauri 参数映射是 JS camelCase ↔ Rust snake_case（`ttlSecs` ↔ `ttl_secs`，与 `targetAddr` ↔ `target_addr` 同规则）。
- 连接方 TTL 校验仍用协议默认 900s：序列号 payload 不含 TTL 字段，属本地校验策略，故未改 connect/connect_lan_code。
- 文档 `feature-inventory.md` §5 设置表、§6.1 G4/G5、§6.2 generate_serial 入参、§11.6 限制 3（划删除线标已解决）均已更新。
